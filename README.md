# 瞬间重构 · 纸世界

> 一个 2020 年提出、2023 年成文的构想：
> **软件的形态可以是临时的，只有数据与语义需要长期存在。**
>
> 这是本仓库的主文档。它不复述细节，只把四份文档的结论串成一条线——
> 每一条判断后面都标了出处，想深挖就点进去。

---

## 1. 一句话，以及它不是什么

> AI 直接生成一件你此刻要用的东西——说不清是菜单还是 APP——
> 用完立即销毁，**但数据保持连续**。

先把三个容易混淆的邻居排除掉：

| 它**不是** | 区别在哪 |
|---|---|
| **超级 APP** | 超级 APP 是"什么都有"，常驻、可发现、有图标。这里是"什么都没有，用的时候才有" |
| **低代码平台** | 低代码产出的是模板和产品，沉淀下来的是资产。这里产出的是**一次性的界面**，沉淀下来的是**数据和判断** |
| **操作系统** | OS 管理常驻进程与资源。这里管理的是**一次动作的展开**，展开完就收起来 |

那它是什么？**软件作为一次事件，而不是一个物件。**

这个说法不是修辞。它对应一个具体的技术判断：过去六十年，软件工程的所有基础设施——
版本管理、向后兼容、灰度发布、十年维护——都建立在"软件是耐用品"这个假设上。
而这个构想把这个假设直接掀了。

---

## 2. 原始构想里，只有四项是真核心

把 2023 年那份原文剥掉科幻叙事，它实际提出的是七件事：

| # | 部件 | 原文主张 | 本质 | 是否核心 |
|---|---|---|---|---|
| 1 | **载体** | 电子纸、可折叠、无穷无尽头 | 硬件形态 | ❌ 可剥离 |
| 2 | **界面** | 每次打开都是空白；功能融合相交，不集成 | 界面不定型 | ★ **核心** |
| 3 | **输入** | 语音、笔、触摸、鼠键、目视 | 多模态入口 | 支撑项 |
| 4 | **转换** | 手写→字体、绘画→表格/网站/知识图谱 | 感知→结构 | ★ 核心输入端 |
| 5 | **语义** | 环境与输入转成"原子化标签"再入库 | 语义层 | ★ **核心** |
| 6 | **生成** | 用户模板 → AI 翻译成"可迭代、高稳定性的产品" | 程序合成 | ★ **核心** |
| 7 | **存储** | 云端 / 盖亚系统 / 区块链激励 | 基础设施 | ❌ 可剥离 |

**这是一条重要的分界线。** 真正构成"纸世界"这个独特想法的，只有 2、4、5、6 四项。
电子纸和盖亚系统是包在外面的未来设定——**拿掉它们，核心照样成立。**

这大概也解释了为什么这个构想放了六年没法动手：**它被硬件叙事绑住了。**
你一直以为要等电子纸，其实不用。

## 3. 三个可检验命题

原话拆开，是三个可以**各自独立成立或证伪**的判断：

| 命题 | 形式化表述 | 2026 年状态 |
|---|---|---|
| **P1 界面不是资产** | 界面 = f(状态, 意图)，随用随算，不必预先存在 | ✅ 已被工业界部分实现 |
| **P2 生命周期短于产品周期** | 生成物寿命 = 本次使用时长，而非软件版本周期 | ⚠️ 组件级已实现，界面级没有 |
| **P3 状态与界面彻底解耦** | 丢弃界面不损失任何信息 | ✅ 已有形式化保证（见第 6 节） |

### "叫菜单还是叫 APP"这个困惑，其实是词汇危机

- 叫**菜单** → 隐含"功能已经存在，我只是把它列出来"。但功能是现生成出来的，不存在索引关系。
- 叫**APP** → 隐含"预装、常驻、有版本号、可卸载"。但它可能只活 90 秒，没有版本，谈不上卸载。

两个词都默认**软件是持久物件**。所以两个都不对。

命名建议（两个都行，看场合）：

| 名字 | 含义 | 用在哪 |
|---|---|---|
| **瞬时界面**（Ephemeral Surface） | 生命周期绑定单次会话、不进持久存储的渲染产物 | 写技术文档，精确 |
| **一页纸**（A Page） | 抽一张、用完揉掉、字已进账本 | 对人解释，直观 |

"一页纸"顺带解掉原文里另一个困惑——"每次打开都是空白"：
**空白不是没有内容，是尚未决定这一页长成什么样。**

## 4. 它像什么

四个正面类比（完整版见 [`03-它像什么.md`](docs/03-它像什么.md)）：

| 类比 | 一句话 |
|---|---|
| **演算纸** | 涂满中间过程，答案誊到卷子上，纸团起来扔掉。扔的时候没有不舍，因为价值已经转移 |
| **栈帧** | 函数调用时在栈上开空间，返回就回收；堆里的东西一直活着。**把界面从堆搬到栈上，数据留在堆里** |
| **剧场** | 布景为这一场戏搭，散场就拆。没人觉得可惜，因为戏不在布景里 |
| **临时工作台** | 清空桌面、摊开工具、修完收起。你不"拥有"它，只**展开过一次作业** |

还有**三个不好听的**——但它们更重要：

| 类比 | 危险 |
|---|---|
| **老虎机** | 拉一下不知道出来什么形状。第一次新鲜，第五次焦虑："为什么昨天那个顺手的样子今天没了？" |
| **被擦掉的白板** | 你画了张特别清楚的图，散会时被擦了。你记得"当时有个特别明白的图"，但画不出来 |
| **回不去的梦** | 梦里那个布局特别合理，醒来知道它存在过，描不出来 |

三者收敛到同一句话：

> **一次性可以，不可回溯不行。**

这也是对原始构想的一条修正：原文说"数据保持不变"，应该是——

> **数据不变，但痕迹留下。**

因为"数据不变"只保住了结果，没保住过程；而人回忆时，回忆的恰恰是过程。
界面的形状是那一瞬间的**解**，你做的动作才是**题**。**存题不存解。**

## 5. 六年后：四家拆开了四样东西

2026 年，四个机构在四个不同层上做了**同一个动作——把"常驻"改成"按需"**。

| 谁 | 拆开的东西 | 手段 | 与本文的关系 |
|---|---|---|---|
| **DeepSeek Harness** | 组件的生命周期 | 可逆效应 + 反应式余效应 + 汇流性定理 | ★ **理论地基** |
| **DeepSeek Engram** | 记忆 / 推理 | 哈希查表 O(1) + DRAM/HBM 冷热分离 | 效率论证 |
| **OpenAI Apps SDK** | 界面 / APP | MCP + 内联 widget（沙箱 iframe + postMessage 桥） | 产品化样板，差一格 |
| **Anthropic Agent Skills** | 规则 / 常驻提示 | 按需加载 + tool schema + hook 强制 | 分层方法论 |

### 学界还泼了一盆冷水

arXiv 2607.27250 做了 288 次对照实验，测 AGENTS.md 是否提升正确率——**无显著差异**。
作者的概括值得贴在桌上：

> **Context 文件是行为方向盘，不是能力注射器。**

翻译过来：**生成式界面提升的是"顺手程度"，不是"任务成功率"。**
如果拿完成率去衡量它，很可能测出一个零。

### 而那一格还是空的

OpenAI 已经做到了"界面在对话里当场渲染、按需出现"，但它生成的是
**"该不该出现、出现哪一个"**——界面本身仍由开发者预制、提交、过审。

```
OpenAI：界面预制，选择生成     ← 已实现，覆盖约 9 亿周活用户
本构想：界面本身生成           ← 仍然空白
```

**这一格，就是这个项目存在的理由。**

## 6. 为什么"销毁"可以是安全的

这是整个构想最容易被人当成空想的地方。但现在它有形式化答案了。

DeepSeek Harness 配套论文
《A Programming Paradigm for Spatiotemporal Composability》（arXiv 2608.25512，
北京大学 + DeepSeek，82 页）把动态组合切成两个正交维度：

| 维度 | 定义 | 大白话 |
|---|---|---|
| **时间可组合性** | 组件移除时，副作用能被完整、安全地回退 | 装得上，也要卸得干净 |
| **空间可组合性** | 组件结构化声明依赖，依赖变化时自动响应 | 依赖谁说得清，且能自动适应 |

论文举的实证很扎人：**VSCode 前 100 名扩展里 87 个含可执行代码，卸载它们全部需要重启整个 Host。**
`deactivate` 钩子只是进程关闭时的回调，运行时用不了；而且它把"副作用销毁"和"副作用产生"
分在两处写——**谁忘写一行谁漏资源，且没有任何机制能发现。**

### 两个机制

**① 可逆效应（管时间）**

一个副作用被建模成：

```
Γ → Γ × (Γ → Γ)
```

作用在当前上下文上，**返回新上下文 + 一个显式的逆函数**。运行时把逆函数累加成"累加器"，
卸载时整体作用一次，环境回到组件来之前的状态。逆函数按施加顺序**前置累积**，天然 LIFO 回收。

两个关键设计：

- **逆函数由施加者在施加的那一刻提供**，不是事后回忆，也不是系统推导
- **复合的逆由组合自动导出**——只写原子逆，拼起来的逆自动成立

**② 反应式余效应（管空间）**

组件把依赖声明成规格；上下文每次变化，系统把变化分类为**激活 / 去激活 / 中性**。
依赖没就绪就不激活，而不是乐观访问再报错。

### 汇流性定理——"数据保持不变"的严格版本

> 不论系统经历怎样一串组件的激活与去激活，
> 它最终静止时的状态，等同于把同样的指令一次性执行、从未卸载所得到的状态。

**生成、使用、销毁，重复一万次，系统状态和"从来没生成过"完全一致。**

这不是愿望，是被证明的性质。

### 由此得到一条工程纪律

> **生成的东西必须自带它的逆。**

运行时**不会**帮你推导怎么撤销。所以"生成界面"这个动作，必须在同一时刻生成它的 cleanup。
否则你造出来的，正是论文批评的 VSCode 那种"拆卸与产生分离"的结构——漏了也没人发现。

**这是整个方案最容易死的地方。**

### 还有一件事：DSH 已经在插件层实现了它

DeepSeek Harness 的**创造模式**允许 agent 检查运行时插件树、动态挂载临时插件，
**任务完成后再卸掉**——这些插件只存在于进程内存，不写文件、不装包、重启即消失。
而它的能力清单里明确包含 **UI**。

```
DSH 已实现：临时生成「能力」→ 用完卸载 → 环境干净
本构想   ：临时生成「界面」→ 用完销毁 → 数据不变
两者的运行时语义，是同一套。
```

**这一格在 DSH 的架构里是合法操作，只是没人把它当主用途。**

> ⚠️ 边界：论文自己写明，语言级访问控制在恶意组件面前不成立。DSH 也把创造模式
> 的信任等级标在 shell 权限上并**默认关闭**。所以"AI 生成即可执行"的信任模型尚未解决。

## 7. 现在能做什么

判据不是"难易"，是**瓶颈类型**——材料问题、制度问题、还是范式问题。

### A 级 · 现在就能做（技术齐备，只差工程）

| # | 能力 | 现成零件 |
|---|---|---|
| A1 | 状态与界面解耦 | 追加日志 + 按需渲染 |
| A2 | 能力层用 MCP | Tools / Resources / Prompts |
| A3 | 生命周期用可逆效应 | Cordis / DSH 的 Context + Effect |
| A4 | 意图 → 形态选择 | 模板选择 + 参数填充（注意：**选形态，不是生成代码**） |
| A5 | 只沉淀用户判断 | 事件日志存"标注 / 选择 / 否决" |
| A6 | **生成即带 cleanup** | 逆函数由调用方提供 |

### B 级 · 1–3 年

受 schema 约束的界面生成、可验证的逆、汇流性测试、行为评估取代回归测试、
端侧小模型做界面合成、**安全边界（必须进程/沙箱级隔离）**

### C 级 · 3–5 年

跨设备语义同步、生成界面的形式化安全保证、多租户隔离、电子纸之前的"软纸"过渡形态

### D 级 · 仍是幻想（请从设计里划掉）

| # | 幻想 | 为什么 |
|---|---|---|
| D1 | 电子纸 / 石墨烯芯片 | 材料与量产，非软件可解 |
| D2 | 盖亚系统 / 区块链存储激励 | 制度设计，且与隐私立法冲突 |
| D3 | "无穷无尽头"的一张纸 | 认知科学问题，不是技术问题 |
| D4 | **完全无预设的界面生成** | 延迟/成本/一致性不可接受，所有实际系统都会退化成"生成配置 + 复用组件" |
| D5 | 实时永久全量历史 | 存储成本与检索质量的矛盾；正解是**只存判断** |

**D4 值得单独说。** 它是这个构想最容易走向极端的一条。
"完全自由的生成"不是目标，**"受约束的生成"才是**——就像 DSH 的创造模式，
临时插件仍跑在 Cordis 的生命周期管理之下，不是凭空乱长。

### 反面清单（比正面清单更有用）

1. 不要从零生成 UI 代码 —— 先生成配置
2. 不要存全量历史 —— 只存判断与被反复请求的意图
3. 不要指望生成式界面提升成功率 —— 它提升的是流畅度（见 §5 那盆冷水）
4. 不要在没有 cleanup 的情况下生成任何东西 —— VSCode 的老坑
5. 不要用提示词写约束 —— 能写成 schema 枚举的，就别用自然语言
6. 不要在信任模型未定时开放"生成即可执行" —— DSH 自己都默认关掉

## 8. 第一个该测的数

不要先搭框架。用两周验证一件事：

**底层**：把一份真实数据写成追加日志，配 3–5 个 MCP 工具
**生命周期**：自己实现极简可逆效应（一个 `effect(fn)` 收逆函数，一个 `unload()` 倒序执行）——
**不需要引入整个 DSH**
**界面**：不生成代码，只做"形态四选一"（卡片 / 表格 / 折线 / 列表）
**每次会话结束必须卸载**，然后比对上下文哈希

要测的三个数：

| 指标 | 怎么测 | 合格线 |
|---|---|---|
| **汇流性** | 生成/销毁 100 次后，上下文哈希是否等于初始 | **必须完全相等** |
| 生成延迟 | 意图 → 界面可用的时间 | 记录基线 |
| 认知成本 | 同一任务，固定界面 vs 生成界面的操作步数 | 生成版应更少 |

**第一个是硬门槛。** 它不过，说明可逆效应实现有漏，后面全是空中楼阁；
它过了，你手里就有一个目前还没有人拿出的证据。
